# location-slides — слайди локацій із заявок форми (Google Apps Script)

Заявка МРМ на локацію приходить Google Формою у таблицю: місто, адреса, площа,
вартість, фото, тип обʼєкта. Для погодження керівництвом на кожну заявку роблять
слайд за корпоративним макетом: місто, таблиця «адреса · площа · вартість ·
вартість за м²», фото, карта мережі «що поруч», рядок «Пропозиція: …». Раніше
слайд збирали вручну по 10–15 хвилин; цей проєкт зводить це до одного вікна
майстра і кнопки «Створити слайд».

Аналіз трьох реальних зразків і всі домовленості — [docs/SPEC.md](docs/SPEC.md).

## Як це працює (пакетний режим, 2026-09-14)

1. **Список заявок** з таблиці форми: усі, в порядку аркуша знизу вгору
   (останній рядок аркуша — перший у списку), з помітками «є слайд» /
   «без слайда»; звужує список лише пошук.
2. Людина **відмічає заявки**, обирає **презентацію** (одна на один розгляд,
   нова створюється копією шаблону) і натискає **«Створити слайди»**.
3. Для кожної заявки, по одній за виклик, сервер збирає слайд сам:
   - **заголовок** — місто; **таблиця** — адреса, площа, вартість, вартість за м².
     Числа підставляються, коли їх можна взяти з форми («800кв.м.» → 800,
     «160000» → 160 000, 160 000 ÷ 800 = 200). Вартість у доларах або текстом
     («Договірна…») іде в таблицю **як є**, вартість за м² тоді порожня;
   - **усі фото заявки** — мініатюрами в сітці зліва, **цілком і без
     обрізання**, оригінальної якості: розтягнув мініатюру — маєш повне фото.
     WebP і HEIC, які Slides не приймає, та фото понад 25 Мпкс ідуть великою
     JPEG-мініатюрою Диска; не-зображення пропускаються з приміткою;
   - **карта «що поруч»** праворуч: знімок, збережений кнопкою 💾 у
     [карті мережі](https://github.com/Pteru4-bit/Network-Map), якщо він є;
     інакше статична карта Google з міткою локації, найближчими **вантажними
     відділеннями** (фіолетові кружки, як на зразках) і плашкою з адресою та
     координатами; координати — з посилання Google Maps у заявці або
     геокодуванням адреси;
   - **«Пропозиція: Відкриття …»** за типом обʼєкта.
4. У рядок заявки пишуться посилання на слайд, дата, автор і презентація.
   Повторний прогін у тій самій презентації замінює слайд.
5. Далі люди **правлять у Презентаціях руками**: прибирають зайві фото,
   збільшують потрібні, міняють карту. Мета автоматики — щоб було що правити.

Застосунок виконується від імені власника (як карта мережі): доступ до файлів
форми, шаблону й презентацій потрібен лише йому, користувачу досить посилання.

## Розгортання

Покроково, з перевірками на кожному етапі — [docs/DEPLOY.md](docs/DEPLOY.md). Коротко:

1. **Шаблон.** Завантажте на Диск будь-який із ручних PPTX (майстер із логотипом)
   і відкрийте його як Google Slides (Файл → Зберегти як Google Презентації).
   Вміст слайдів не важливий — усе, крім першого, видалиться при створенні презентації.
   Запишіть ID.
2. **Проєкт.** [script.new](https://script.new) → «Слайди локацій» → перенесіть
   `src/` (скрипти `.gs` як Script, `Wizard*.html` як HTML, `appsscript.json`
   через «Показувати маніфест»). Або clasp: `.clasp.json` з `"rootDir": "src"`.
3. **Налаштування** — `src/Config.gs` або Script Properties з такими ж іменами
   малими літерами:
   - `RESPONSES_SS_ID` — таблиця відповідей форми (`RESPONSES_SHEET` — якщо
     аркуш не «Відповіді…»);
   - `TEMPLATE_DECK_ID` — шаблон із кроку 1;
   - `MAP_SHOTS_FOLDER_ID` — папка карт; створити `initMapShotsFolder()` тут
     **або** `initSlideShotsFolder()` у карті — ID один на обидва проєкти;
   - `MAP_WEB_APP_URL` — URL веб-застосунку карти мережі (потрібна її версія
     2026-09 з кнопкою 💾, див. DEPLOY карти, розділ 8в);
   - `DECKS_FOLDER_ID` — куди складати презентації (необовʼязково);
   - `ALLOWED_EMAILS` — кому відкривати майстер (порожньо = весь домен).
4. У редакторі виконайте `initDataSpreadsheet()` (таблиця «Презентації» + «Лог»), потім
   `checkSetup()` — журнал покаже, що знайдено, і як лягли колонки форми.
   Якщо колонка визначилась не так, поправте `CFG.COLS` (шаблон заголовка або
   літеру) і перевірте `debugHeaders()`.
5. **Деплой:** Розгорнути → Веб-застосунок → виконувати як **я**, доступ —
   **усі в домені**. Посилання роздайте тим, хто робить слайди.

Службові колонки «Слайд», «Слайд: оновлено», «Слайд: ким», «Слайд: презентація»,
«Координати» майстер допише в аркуш відповідей сам, праворуч від колонок форми.

## Структура

```
├─ docs/SPEC.md          # специфікація: зразки, колонки, макети, потоки
├─ src/
│  ├─ Config.gs          # налаштування, колонки форми, ініціалізація
│  ├─ Parse.gs           # чисті функції розбору (тестуються в node)
│  ├─ Sheet.gs           # таблиця відповідей: колонки, рядки, зворотний запис
│  ├─ Photos.gs          # файли Диска: мініатюри, картинки для слайда, знімки карти
│  ├─ Geo.gs             # координати: посилання Maps → геокодер
│  ├─ Decks.gs           # реєстр презентацій, нова презентація з шаблону, лог
│  ├─ SlideBuilder.gs    # побудова слайда: таблиця, сітка фото, карта, пропозиція
│  ├─ Code.gs            # doGet + API майстра, checkSetup()
│  └─ Wizard*.html       # майстер (HTML, CSS, JS)
└─ tools/
   ├─ parse-test.js      # node tools/parse-test.js — розбір на трьох реальних рядках
   └─ wizard-ui-test.js  # node tools/wizard-ui-test.js — пакетний режим у браузері (Playwright)
```

Тести не потребують Google: `parse-test` виконує `Parse.gs` як є, а
`wizard-ui-test` підставляє замість `google.script.run` заглушку з даними
трьох реальних заявок. Playwright: `NODE_PATH=$(npm root -g)` якщо він
встановлений глобально.
