# Слайди локацій — специфікація

Зафіксовано за обговоренням 2026-09-10 на трьох реальних зразках (Чернігів,
Чернівці, Київ): рядок форми + слайд, який людина зробила з нього вручну.

## 1. Вхідні дані: таблиця відповідей форми

Колонка A — позначка часу подачі, тому це аркуш відповідей Google Форми. Літери
нижче — як у трьох зразках; проєкт шукає колонки за заголовками і бере літеру
лише як запасний варіант (`CFG.COLS`).

| Колонка | Зміст | На слайд | Примітка |
|---|---|---|---|
| A | позначка часу | ні | **ключ рядка** `yyyyMMdd-HHmmss` |
| B | дата огляду | ні | |
| C | хто подав (МРМ) | ні | |
| D | область | ні | у запиті геокодера |
| E | місто | **заголовок** | пробіли обрізаються («Київ ») |
| F | адреса | таблиця | без номера будинку геокодер дає приблизно |
| G | оренда / купівля | ні | |
| H | площа | таблиця | текст: «1000», «800кв.м.», «до 5 300» → число |
| I | вартість | таблиця | «160000», «Договірна…», «від 15 $/м²…» — число лише коли гривні за весь обʼєкт |
| J | «Кількість рамп» | ні | людина за потреби пише в «Примітку» |
| K | «Наявність автодвору» | ні | показується в майстрі |
| L, M, U | «Фото локації ззовні», «…всередині», «Фото автодвору» | картинки | посилання `drive.google.com/open?id=`, кілька через кому; U буває порожня |
| N | «Посилання на оголошення або КП» | ні | посилання або вільний текст |
| O | «Підходить для:» | «Пропозиція: Відкриття …» | «Відділення», «Депо/термінал»; **«Не підходить» = слайд не потрібен**, майстер ховає такі заявки за замовчуванням |
| P, Q, R | «Дата передачі локації РД ТЛ», «ПІБ РД ТЛ», «Причина відмови…» | ні | заповнюються після розгляду |
| S | «Регіон» | ні | |
| T | «Звідки локація» | ні | «Рієлтор», «МРМ знайшов самостійно» |
| V | «Посилання на Google Maps» | координати | `@lat,lng` або `!3d!4d`, буває порожня |
| W | «Відео 360 градусів» | ні | посилання в майстрі |

Заголовки зняті з реальної таблиці «Опрацьовані локації (Відповіді)», аркуш
«Відповіді форми (1)» (checkSetup(), 2026-09-10).

Службові колонки, які проєкт додає праворуч: «Слайд» (посилання на слайд),
«Слайд: оновлено», «Слайд: ким», «Слайд: презентація», «Координати».

## 2. Слайд: що з чого

Формат 16:9, 13,33 × 7,5 дюйма, майстер Нової Пошти (логотип унизу праворуч).

| Елемент | Геометрія, дюйми | Джерело |
|---|---|---|
| Місто, 36 pt, жирний, `C00000` | 0,16 · 0,10 · 5,45 × 0,71 | E |
| Таблиця 2×4: Адреса · Площа м2 · Вартість загальна в грн · Вартість м2; заголовок сірий | 4,19 · 0,10 · 8,25 × 0,91; колонки 1,98 / 1,78 / 2,25 / 2,25 | F, H, I (або введене), вартість ÷ площа |
| Картинки, макет **row** (1–3) | y 1,37, h 3,64; x 0,05 / 4,47 / 8,89, w 4,37 | фото у вибраному порядку, карта остання |
| Картинки, макет **grid** (4–5) | верх: y 1,01, h 3,40, ті самі x; низ: y 4,50, h 2,85, x 0,05 / 4,47 | те саме |
| Примітка під фото, 16 pt | row: 0,16 · 5,13; grid: 9,05 · 5,95 | введене (необовʼязково) |
| «Пропозиція: …», 24 pt, жирний, `201E1D` | row: 3,30 · 5,85 по центру; grid: 9,05 · 4,55 | «Відкриття {тип}» або введене |

Картинки заповнюють слот повністю з обрізанням по центру (так робили вручну).
На слайд іде JPEG-мініатюра Диска шириною 1600 px — це нормалізує формат (WebP,
HEIC) і розмір; PNG-знімки карти вставляються як є.

Що людина у зразках дописувала від себе, і як це вирішено:

- **вартість**: 100 000 грн при «Договірна» і 3 577 500 грн при «15 $/м²» (15 × 5300 × 45) —
  поле «Вартість, грн» у майстрі, обовʼязкове, коли у формі не число в гривнях;
- **підпис «Рампи під орендаря (до 5шт)»** — поле «Примітка», порожнє за замовчуванням;
- **«Відкриття ДЕПО або АО» / «терміналу»** — поле «Пропозиція» з підставленим
  «Відкриття {тип}», редагується.

## 3. Рішення, прийняті користувачем

1. Рядки для слайдів відмічає той, хто робить слайд; слайди робляться до
   розгляду для всіх, кого відібрав координатор.
2. Кількість фото та які саме — обирає людина при створенні (мініатюри з
   галочками і порядком). Максимум 5 картинок разом із картою.
3. Вартість у доларах — людина вписує гривні сама при створенні.
4. Карта — варіант «Зберегти карту в Drive»: кнопка в карті мережі, файл
   підхоплюється майстром за ключем заявки. Запасний шлях — завантажити файл.
5. Результат — Google Slides за посиланням.
6. Колонка U — фото, може бути порожньою.
7. Одна презентація на один розгляд.

## 4. Потоки

**Створення слайда.** Список заявок → заявка → майстер підставляє дані →
людина править таблицю/тексти, обирає фото, карту й презентацію → «Створити слайд» →
слайд у презентації, у рядок записано посилання/дату/автора/презентацію, координати
збережено, лічильник презентації оновлено, запис у «Лог».

**Карта.** Координати: «Координати» з рядка → посилання Maps (V) →
геокодер (D+E+F). «Відкрити карту мережі» → `MAP_WEB_APP_URL?slide=<ключ>&ll=lat,lng&z=15&label=…`
→ у карті мітка 📍, кнопка 💾 → `slide-<ключ>-<час>.png` у спільній папці →
у майстрі «Оновити список» (або автоматично при поверненні на вкладку) →
знімок обрано.

**Повтор.** Заявка зі слайдом у тій самій презентації → кнопка «Оновити слайд у цій
презентації» → старий слайд видаляється, новий стає на його місце. В іншій презентації —
новий слайд, посилання в рядку оновлюється.

## 5. Обмеження і ризики

- Apps Script: 6 хвилин на виконання — один слайд це 10–30 с, партія робиться
  по одному слайду з майстра, без фонової черги.
- Мініатюра Диска для щойно завантаженого файлу може зʼявитись із затримкою —
  майстер покаже, який файл не відкрився; спроба за хвилину.
- Геокодер без номера будинку дає центр вулиці або району — майстер попереджає,
  координати можна виправити вручну або взяти з карти.
- Обрізання картинок і рамки таблиці ставляться через Slides API (advanced
  service); якщо він недоступний, картинки вписуються без обрізання, слайд
  усе одно створюється, у відповіді є пояснення.
- Заглушка шаблону: у новій презентації лишається перший слайд шаблону з міткою в
  нотатках; він зникає з першим справжнім слайдом.

## 7. Пакетний режим (рішення 2026-09-14)

Після перших живих запусків ціль змінено: не збирати слайди по одному з
ручним вибором, а **відмітити заявки, зібрати слайди масово і потім пройтись
руками в Презентаціях**. Що змінилось:

| Було (майстер по одній) | Стало (пакет) |
|---|---|
| людина обирає фото та їх порядок | **усі фото заявки** (до `PHOTO_MAX`, 20) у сітці зліва |
| фото обрізані під слот, JPEG 1600 px | фото **цілком, без обрізання**, **оригінал** (`IMAGE_MAX_PX = 0`); розтягнув — повна якість |
| вартість у гривнях вводить людина, без неї слайд не збирається | число, коли воно є у формі; інакше **текст із форми як є**, вартість за м² порожня |
| карту робить людина кнопкою 💾 у карті мережі | знімок 💾 підхоплюється, якщо є; інакше **статична карта Google** з точками мережі будується сама |
| один слайд за раз, форма з полями | список із галочками, презентація, «Створити слайди (N)», журнал ходу, «Зупинити» |

Розкладка (уточнено 2026-09-14 після порівняння з ручним слайдом Житомира):
верхній ряд із трьох клітинок 4,37 × 3,64 (y 1,37) — **перші два фото і
карта останньою**, як на зразках; без карти — три фото. Решта фото —
**смугою мініатюр** 8,74 × 1,80 (y 5,10) ліворуч, сітка обирається за
пропорціями кожного фото так, щоб сумарна площа була найбільшою (`bestGrid`:
вертикальні фото стають в один ряд, горизонтальні — у два-три). «Пропозиція»
— праворуч від смуги (20 pt) або внизу по центру (24 pt), коли решти фото
немає. Фото ніде не обрізаються.

Таблиця: клітинки Google Slides мають вбудовані поля 0,1", яких API не міняє,
тому шрифти менші за PowerPoint-оригінал (заголовок 12 pt, значення 11 pt),
колонки 1,85 / 1,55 / 2,60 / 2,25 — разом висота ≈ 0,8", як в оригіналі.
Нотатки слайда порожні; службові подробиці (фото, карта, координати) — у
журналі клієнта і в аркуші «Лог».

Точки мережі для статичної карти читаються з `map-network-payload.json` —
файлу, який карта мережі тримає на Диску того самого власника (gzip+base64
JSON з масивом `points` `[lat, lng, тип, підтип, …]` і словником `subs`).
Масштаб за типом обʼєкта (`CFG.MAP.zoomByType`: відділення z14, депо/термінал
z13), у кадр беруться до 60 найближчих точок **лише вантажних відділень**
(`CFG.MAP.categories: ['cargo']`, фіолетові кружки — як на ручних зразках;
порожній список = усі категорії). Поверх карти — біла плашка з адресою
(жирним) і координатами, як попап на знімках карти мережі; знімок 💾 уже
містить свій попап, тож для нього плашка не додається. Немає файлу витягу —
карта лише з міткою локації. Немає координат — карти немає, причина в
журналі.

Один виклик сервера = один слайд (10–60 с залежно від кількості й розміру
фото); клієнт іде по відмічених заявках по черзі, помилка однієї не зупиняє
решту, невдалі лишаються відміченими для повтору.

## 6. Що не зроблено свідомо

- Автоматична конвертація доларів за курсом — користувач вирішив вписувати
  гривні вручну.
- Слайд-продовження для 6+ фото — людина обирає до чотирьох фото плюс карту.
- Статична карта без участі людини (`Maps.newStaticMap`) — обрано знімок
  справжньої карти мережі.
