# Розгортання «Слайдів локацій» (покроково)

Кроки 1–9 адміністратор робить один раз. Крок 10 — щоденна робота тих, хто
робить слайди. Обидва застосунки (карта й слайди) розгортаються від імені
одного власника: тоді доступ до файлів форми, шаблону, дек і папки карт
потрібен лише йому.

## А. Оновити карту мережі (проєкт Network-Map)

1. У редакторі Apps Script карти створіть новий файл **`SlideShot.gs`** і
   замініть вміст **`Code.gs`**, **`Config.gs`**, **`Map.html`**,
   **`Map_css.html`**, **`Map_js.html`** файлами з репозиторію Network-Map
   (гілка з оновленням 2026-09; детальніше — його `docs/DEPLOY.md`, розділ 8в).
2. Виконайте **`initSlideShotsFolder()`**. У журналі виконання буде ID папки
   «Карти для слайдів локацій» — скопіюйте його для кроку 7.
3. Розгорнути → Керування розгортаннями → нова версія. Скопіюйте URL
   веб-застосунку (закінчується на `/exec`) для кроку 7.
4. Перевірка: відкрийте цей URL з хвостом
   `?ll=51.53568,31.25321&z=15&slide=test`. Має стояти мітка 📍 і зʼявитись
   підказка про 💾. Натисніть 💾 — у папці з кроку 2 зʼявиться
   `slide-test-<час>.png`, у «Логах» карти — рядок «карта для слайда».

## Б. Шаблон

5. Завантажте на Диск будь-який із ручних PPTX (наприклад, Чернігів), відкрийте
   його через Google Презентації, далі **Файл → Зберегти як Google
   Презентації**. Скопіюйте ID з адреси файлу. Вміст слайдів не важливий: при
   створенні деки все, крім першого слайда, видаляється, а перший зникає з
   першим справжнім слайдом. Лишається майстер із логотипом і шрифтами.

## В. Створити проєкт «Слайди локацій»

6. [script.new](https://script.new) → назва «Слайди локацій». Створіть файли з
   папки `src/` цього репозиторію:

   | Файл у репо | Тип в Apps Script |
   |---|---|
   | Code.gs, Config.gs, Parse.gs, Sheet.gs, Photos.gs, Geo.gs, Decks.gs, SlideBuilder.gs | Script |
   | Wizard.html, Wizard_css.html, Wizard_js.html | HTML (той самий регістр назв!) |
   | appsscript.json | Налаштування проєкту → «Показувати маніфест appsscript.json» → замінити вміст (там підключені сервіси Drive і Slides) |

   Або clasp: `.clasp.json` з `{"scriptId":"…","rootDir":"src"}` → `clasp push`.
7. Налаштування проєкту → **Властивості скрипту** → додайте:

   | Властивість | Значення |
   |---|---|
   | `responses_ss_id` | ID таблиці відповідей форми (з адреси таблиці) |
   | `template_deck_id` | ID шаблону з кроку 5 |
   | `map_shots_folder_id` | ID папки з кроку 2 |
   | `map_web_app_url` | URL карти з кроку 3 |

   Необовʼязково: `responses_sheet` (якщо аркуш не «Відповіді…»),
   `decks_folder_id` (куди складати деки), а в `Config.gs` — `ALLOWED_EMAILS`
   (кому відкривати майстер; порожньо = весь домен). Значення можна вписати і
   прямо в `Config.gs` — вони мають пріоритет над властивостями.
8. У редакторі виконайте **`initDataSpreadsheet()`** (перший запуск попросить
   дозволи — надайте всі; створиться таблиця «Слайди локацій — дані» з
   аркушами «Деки» і «Лог»). Потім **`checkSetup()`** і прочитайте журнал:
   таблиця, шаблон, папка карт і рядки «колонка → …» про те, як лягли колонки
   форми. Якщо якась визначилась не туди — поправте в `Config.gs` блок `COLS`
   (шаблон заголовка або літеру) і перевірте **`debugHeaders()`**.
9. Розгорнути → **Веб-застосунок** → виконувати як **я**, доступ — **усі в
   домені**. Посилання роздайте тим, хто робить слайди.

Службові колонки «Слайд», «Слайд: оновлено», «Слайд: ким», «Слайд: дека»,
«Координати» майстер допише в аркуш відповідей сам при першому відкритті,
праворуч від колонок форми.

## Г. Як робиться один слайд

10. Відкрити майстер → обрати заявку зліва (фільтр «лише без слайда» і пошук).
    Перевірити площу й вартість; якщо у формі долари або текст — вписати суму
    в гривнях, інакше слайд не збереться. Обрати фото й порядок. Натиснути
    **«Відкрити карту мережі»** → у карті скомпонувати кадр, натиснути **💾**,
    дочекатись «Карту збережено» → повернутись у майстер: знімок підтягнеться
    сам (або «↻ Оновити список»). Обрати деку або **«+ Нова дека»** для нового
    розгляду. **«Створити слайд»** → посилання на слайд у майстрі й у рядку
    заявки. Наступна заявка — кнопкою в результаті.

## Якщо щось не так

| Симптом | Дія |
|---|---|
| Майстер пише «Не задано RESPONSES_SS_ID» | властивість `responses_ss_id` не збережена або з помилкою в імені (малі літери) |
| У списку не ті поля (місто в адресі тощо) | `checkSetup()` → рядки «колонка → …»; поправте `CFG.COLS` |
| Фото «не відкрився» | Диск ще не зробив мініатюру щойно завантаженого файлу — спробуйте за хвилину; або файл недоступний власнику |
| «Не задано MAP_SHOTS_FOLDER_ID» | властивість `map_shots_folder_id`; той самий ID має стояти в карті |
| Немає кнопки «Відкрити карту мережі» | порожній `map_web_app_url` |
| «Оберіть або створіть деку» / «Не задано TEMPLATE_DECK_ID» | крок 5 і властивість `template_deck_id` |
| Слайд створено, але картинки не обрізані, у відповіді примітка про API | сервіс Slides не підключений у маніфесті або без дозволу — перевірте `appsscript.json`, перевидайте; слайд усе одно правильний |
| Координати «знайдено приблизно» | адреса без номера будинку — виправте координати в майстрі або візьміть із карти |
